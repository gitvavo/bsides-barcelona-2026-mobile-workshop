01 Create your Android emulator

Use Android 14 (API 34), AOSP, x86_64 on Windows or x86_64 Linux/Intel macOS. Avoid the Google Play image: the Frida exercise requires adb root. An Android Studio Device Manager workflow works on all three platforms.

Apple Silicon: use an ARM64 AOSP API 34 image instead. The bundled Frida Server ZIP is x86_64 only; download the matching ARM64 server of the same Frida version separately. Do not try to run the x86_64 server on an ARM64 emulator.

Windows · PowerShell

  1. In your BIOS/UEFI, enable Intel VT-x or AMD-V. On Windows, enable Windows Hypervisor Platform and restart if needed.
  2. Install Android Studio (recommended) and let its setup wizard install Android SDK, Android Emulator and Platform Tools. Install a JDK 17 or later if using standalone SDK command-line tools; Android Studio includes a JDK for its own tooling.
  3. Alternatively, install the official Android CLI and reopen PowerShell before trying android:
winget install --id Google.AndroidCLI
# Open a NEW PowerShell session, then:
android sdk install platform-tools emulator platforms/android-34
android sdk list --all

In Android Studio → Tools → Device Manager → Create Virtual Device, choose a phone and the API 34 AOSP x86_64 system image. You can download the image in SDK Manager if it is not yet listed.

If adb or emulator isn't recognized, open a new PowerShell window after installation and add your actual SDK platform-tools and emulator directories to PATH, or run those tools using their full paths.

Linux · Bash

  1. Enable VT-x/AMD-V in BIOS/UEFI. Verify /dev/kvm exists and your user has permission to access it (commonly membership in the kvm group; log out and back in after changing group membership).
  2. Install a JDK (e.g. OpenJDK 17) through your distribution and verify java -version.
  3. Install Android Studio and the Android SDK components from SDK Manager (Android 14 SDK Platform, SDK Platform-Tools, Android Emulator and the API 34 AOSP x86_64 system image).
java -version
ls -l /dev/kvm
# In Android Studio: Tools → Device Manager → Create Virtual Device
# Choose Android 14 (API 34), AOSP, x86_64.

After changing PATH or JAVA_HOME, reopen your terminal or source the appropriate shell profile; after joining the kvm group, log out and sign back in.

macOS · Terminal

  1. Install Android Studio, and select SDK Platform 34, Platform-Tools, Android Emulator and an API 34 AOSP image in SDK Manager.
  2. On an Intel Mac select x86_64. On an Apple Silicon Mac select ARM64, and obtain the matching ARM64 Frida Server; the supplied x86_64 ZIP won't run.
  3. If using standalone SDK tools, install JDK 17 or later (Android Studio normally supplies its own JDK) and confirm it is available to your terminal.
java -version
uname -m
# In Android Studio: Tools → Device Manager → Create Virtual Device
# Choose API 34 / AOSP and your host-compatible architecture.

Open a new Terminal after installing tools or updating PATH/JAVA_HOME. Apple's hypervisor normally handles acceleration; there is no PC BIOS virtualization setting.

Recommended virtual device configuration

  • Android 14 / API 34; AOSP, not Google Play. For Windows, Intel Mac and x86_64 Linux: x86_64.
  • Screen 1080 × 1920, density 480 dpi, data partition 10 GB and hardware keyboard input enabled (configure Advanced Settings or the AVD's config.ini).
  • Name it Mockapp_API_34. If the AVD editor doesn't expose a custom resolution, choose a phone profile and leave its default display; the exercises don't depend on pixel dimensions.

Boot and verify

Start the virtual device from Android Studio's Device Manager. Once fully booted, run:

adb devices
adb shell getprop ro.build.version.sdk
adb shell getprop ro.product.cpu.abi
adb root
adb shell id

Expected: a connected emulator-5554 (the number can differ), API 34, the expected CPU ABI, and uid=0(root) after adb root. If adb root says adbd cannot run as root in production builds, recreate the AVD using the non-Play AOSP image. If adb devices says unauthorized, accept the device authorization prompt.

You can also use the SDK command-line AVD tools if already installed: sdkmanager "system-images;android-34;default;x86_64", then avdmanager create avd -n Mockapp_API_34 -k "system-images;android-34;default;x86_64", then emulator @Mockapp_API_34. These commands require SDK Command-line Tools on PATH and an available default x86_64 image.

02 Start the backend

With your Android emulator created, install Docker Desktop/Engine and start the local workshop backend.

docker compose up -d --build
docker compose ps

Open http://localhost:8080 to access the exercises, reset and status checks. All Docker ports are bound to your computer's loopback interface.

If Docker reports a missing daemon pipe on Windows, start Docker Desktop first.

03 Install Mockapp

Download the debug APK from Downloads. Verify ADB sees your emulator and install the APK:

adb devices
adb install -r mockapp-home-lab-v0.5.0-debug.apk

Default HTTPS backend: https://10.0.2.2:9443. HTTP mode uses port 8000. The address 10.0.2.2 is an emulator-only alias to the host machine.

Demo credentials: alice / coffee1042 or bob / coffee1043.

04 Configure Burp Suite

  1. Load the supplied Burp project settings JSON in Burp.
  2. Verify the proxy listener is running at 127.0.0.1:8088 and Redirect to host = 127.0.0.1, with redirect port left blank.
  3. Open the listener's Certificate settings, choose custom certificate, browse to mockapp-burp.p12 on your computer, and enter the supplied password. The JSON cannot carry a portable local absolute path.
  4. Copy the supplied public CA into Android:
adb push lab-ca.crt /sdcard/Download/lab-ca.crt

Inside Android: Settings → Security & privacy → More security & privacy → Encryption & credentials → Install a certificate → CA certificate. Select the downloaded CA.

Set the visible Android Wi-Fi proxy

Android Settings → Network & internet → Internet → AndroidWifi → Edit → Advanced options → Proxy → Manual. Hostname: 10.0.2.2, port: 8088. Save.

Wi-Fi proxy walkthrough

Don't use the separate Android Emulator Extended Controls upstream proxy. After testing, return to Android Wi-Fi settings and choose Proxy: None.

05 Start Frida Server

Download the Frida Server x86_64 ZIP and the pinning bypass JavaScript from Downloads. Extract the ZIP; it contains an executable named frida-server. Use desktop Frida 17.24.3 to match the supplied server.

adb shell getprop ro.product.cpu.abi
adb root
adb shell id
adb push frida-server /data/local/tmp/frida-server
adb shell chmod 755 /data/local/tmp/frida-server
adb shell "/data/local/tmp/frida-server >/dev/null 2>&1 &"
frida-ps -U

From the directory containing the bypass script:

frida -U -l ./bypass-mockapp-pinning.js -f com.mockapp.loyalty

Frida Server must be restarted after rebooting the emulator. If ADB root is refused, switch to a root-capable AOSP image.

06 Run the exercises

Open the seven exercises. Each has independently selectable hint levels (No hint, Level 1, Level 2 and Level 3). If you get stuck, the solutions are available whenever you want them.

To switch Mockapp's transport mode, tap ⚗ Lab Testing and force-stop / reopen the app:

adb shell am force-stop com.mockapp.loyalty
adb shell monkey -p com.mockapp.loyalty -c android.intent.category.LAUNCHER 1

Use the Lab Settings panel to reset users, balances, sessions and rewards.
